## Practical tip: lambda offset for frequently changing placement

**Problem.** Reading rapidly changing position state while constructing a modifier in composition can cause unnecessary composition work. Compose offers an offset overload that defers the read until placement. This does not make every offset cheaper and is not a substitute for measuring real frame performance.

**Complete reusable composable (not a complete Activity or automated test):**

```kotlin
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.offset
import androidx.compose.foundation.layout.size
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.foundation.layout.Column
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableIntStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.IntOffset
import androidx.compose.ui.unit.dp

@Composable
fun DeferredOffsetExample() {
    var offsetPx by remember { mutableIntStateOf(0) }

    Column {
        Button(onClick = { offsetPx += 10 }) {
            Text("Move 10 px")
        }
        Box(
            modifier = Modifier
                .size(64.dp)
                .offset { IntOffset(x = offsetPx, y = 0) }
                .background(Color.Blue)
        )
    }
}
```

The lambda overload uses **physical pixels** via `IntOffset`, whereas `offset(x = 10.dp)` accepts dp. Both change placement without changing the parent's measurement constraints or the layout space reserved for the child. The lambda reads `offsetPx` during the layout/placement phase; this can avoid invalidating composition for this particular read. The Button and other readers may still cause recomposition; do not assert zero recompositions.

**Reproduce / debug / review**

- [ ] Compare the lambda form with `Modifier.offset(x = (offsetPx / density).dp)` only after controlling density and integer rounding; prefer a separate fixed-dp example to avoid conversion mistakes.
- [ ] Use Layout Inspector or Compose tracing to identify composition, measure and placement work rather than assuming that fewer recompositions imply fewer frames or better performance.
- [ ] Verify hit targets and overlap with siblings: offset changes placement, not the space reserved by the parent.
- [ ] Check RTL behavior: `offset` is layout-direction-aware; use `absoluteOffset` only if that is the intended contract.
- [ ] For animations, compare with graphics-layer translation and test semantics/hit testing before changing modifier strategy.
- [ ] Measure performance and capture screenshots at the target density. **No build, tracing, screenshot or benchmark was executed for this article.**
