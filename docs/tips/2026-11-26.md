## Practical tip: identity and observable state

Strong skipping is enabled by default since Kotlin 2.0.20. Unstable parameters are compared by identity, stable parameters by equality. Mutating an ordinary mutable list in place neither creates a new identity nor automatically invalidates snapshot readers. Do not annotate mutable models as immutable to force skipping.

Complete reusable composable, not a complete Activity:

```kotlin
import androidx.compose.foundation.layout.Column
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

@Composable
fun SelectionList() {
    var labels by remember { mutableStateOf(listOf("A")) }
    Column {
        Button(onClick = { labels = labels + "B" }) {
            Text("Add")
        }
        Labels(labels)
    }
}

@Composable
private fun Labels(labels: List<String>) {
    Text(labels.joinToString())
}
```

The replacement writes observable state and changes the list identity. Kotlin List is a read-only interface, not a guarantee of deep immutability. For intentional in-place observable collection updates consider mutableStateListOf and ensure readers observe its contents.

## Reproduce and review

- Click Add; expect A, B. Repeat and expect another B.
- Negative control: use a remembered ordinary mutableListOf and mutate it without observable state; do not expect automatic UI invalidation.
- Inspect compiler stability reports and Layout Inspector recomposition/skip counts. Unstable does not mean always recomposed under strong skipping.
- Do not infer frame-time improvement from skip counts; measure separately.
