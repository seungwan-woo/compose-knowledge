## 출시 확인

공식 목록에서 2026-11-24~2026-11-25 KST에 새 Compose 그룹 출시를 찾지 못했습니다. 목록의 최신 출시일은 11월 18일입니다. UI/Foundation/Runtime/Animation/Material은 1.13.0 안정 버전과 1.14.0-alpha01, Material3는 1.5.0 안정 버전과 1.6.0-alpha01입니다. BOM 매핑에는 1.13.0이 포함되어 있습니다. 정확한 최신 BOM 식별자와 도구, 테스트, 접근성, 성능 관련 개별 커밋은 확인하지 못했습니다.

## 실전 팁 — 키를 받는 SideEffect

성공한 컴포지션 이후 Compose 외부 객체에 값을 동기적으로 전달하되, 컴포지션에 진입하거나 키가 바뀔 때만 전달하려면 키를 받는 오버로드를 사용하세요. 이 오버로드는 코루틴을 시작하거나 정리 콜백을 제공하지 않습니다. 키가 없는 `SideEffect`는 호출 지점에서 리컴포지션에 성공할 때마다 실행됩니다. 키가 있는 오버로드는 키가 그대로면 실행을 건너뜁니다.

다음은 재사용 가능한 컴포저블과 값을 받는 일반 Kotlin 클래스 전체입니다. Activity는 포함하지 않습니다.

```kotlin
import androidx.compose.runtime.Composable
import androidx.compose.runtime.SideEffect

class SelectionSink {
    var selectedId: Long? = null
        private set

    fun publish(id: Long) {
        selectedId = id
    }
}

@Composable
fun PublishSelection(selectedId: Long, sink: SelectionSink) {
    SideEffect(selectedId, sink) {
        sink.publish(selectedId)
    }
}
```

관련 없는 리컴포지션에서 값을 받는 객체를 같은 인스턴스로 유지하세요. 객체를 키에 포함하면 교체된 객체도 현재 선택을 받습니다. 작업은 짧게 끝내고 차단 호출을 피하세요. 일시 중단이 필요한 작업에는 `LaunchedEffect`를, 해제가 필요한 등록 작업에는 `DisposableEffect`를 사용하세요. 컴포지션에서 나갔다가 다시 들어오면 값이 다시 전달될 수 있으므로 지속적으로 정확히 한 번만 이벤트를 전달하는 용도로는 적합하지 않습니다.

### 재현 및 검토

- ID 1과 계속 유지되는 수신 객체로 컴포지션을 구성합니다. 값 1이 전달되어야 합니다.
- 키를 유지한 채 관련 없는 부모 리컴포지션을 일으킵니다. 추가 전달이 없어야 합니다.
- ID를 2로 바꿉니다. 값 2가 전달되어야 합니다. 수신 객체를 새 인스턴스로 바꾸면 새 객체 역시 2를 받아야 합니다.
- 컴포저블을 제거했다가 다시 삽입합니다. 값이 다시 전달되어야 합니다. 수신 객체에 카운터를 추가해 반복 쓰기를 구분합니다.
- 차단 I/O, 상태 피드백 루프, 누락된 정리 작업이 없는지 확인합니다. 여기 적은 내용은 예상 결과이며 테스트를 실행하지 않았습니다.

### 버전 및 도구 체인

키를 받는 `SideEffect`는 Runtime 1.12.0-alpha02(2026년 5월 6일)에 처음 나왔으며, 안정 버전 1.12.0(2026년 8월 12일)에 포함되었습니다. 키 없는 `SideEffect`는 1.0.0 계열부터 제공됩니다. 기준 버전은 Runtime 1.13.0 안정 버전입니다. 안정 버전의 오버로드에는 실험 기능 옵트인이 필요하지 않을 것으로 예상됩니다. 이 API에 별도의 AGP 최소 버전은 없습니다. Runtime 1.12 alpha01 출시 노트는 API 37과 AGP 9.2를 최소 요구사항으로 명시하고, Compose 1.13 출시 노트는 compileSdk 37.1과 Kotlin 컴파일러 2.2를 명시합니다. 실제로 해석된 AAR 메타데이터를 확인하고 필요한 SDK를 공식 지원하는 AGP를 선택하세요. AGP 9.2는 API 37.0을 지원하며 Gradle 9.4.1과 JDK 17을 사용합니다. 37.1 호환성은 확인되지 않았습니다. Kotlin 버전에 맞는 Compose 컴파일러 플러그인을 사용하세요. AGP 9.5 전용 실험 기능은 사용하지 않았습니다. 빌드와 테스트는 **실행하지 않았습니다**.

## 저녁 팁(2026-11-25) — UI 테스트를 고치기 전에 병합된 시맨틱과 병합되지 않은 시맨틱 살펴보기

Compose 테스트의 기본 파인더는 병합된 시맨틱 트리를 검색합니다. 맞춤 구성요소는 자식의 라벨을 하나의 동작 가능한 노드로 병합할 수 있습니다. 테스트를 통과시키기 위해 프로덕션 시맨틱을 바꾸기 전에 두 트리를 살펴보세요.

다음은 계측 테스트 클래스 전체입니다. Compose를 사용하는 Android 모듈에 Foundation, Material3, JUnit4, `ui-test-junit4`, 디버그용 `ui-test-manifest`가 필요합니다.

```kotlin
import androidx.compose.foundation.layout.Row
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.ui.Modifier
import androidx.compose.ui.platform.testTag
import androidx.compose.ui.test.junit4.createComposeRule
import androidx.compose.ui.test.onNodeWithTag
import androidx.compose.ui.test.onRoot
import androidx.compose.ui.test.printToLog
import androidx.compose.ui.test.performClick
import org.junit.Assert.assertEquals
import org.junit.Rule
import org.junit.Test

class MergedSemanticsTest {
    @get:Rule
    val rule = createComposeRule()

    @Test
    fun actionAndChildSemantics() {
        var clicks = 0
        rule.setContent {
            Button(
                onClick = { clicks++ },
                modifier = Modifier.testTag("save_action")
            ) {
                Row {
                    Text("Save", Modifier.testTag("save_label"))
                }
            }
        }
        rule.onRoot().printToLog("Merged")
        rule.onRoot(useUnmergedTree = true).printToLog("Unmerged")
        rule.onNodeWithTag("save_action").performClick()
        rule.runOnIdle { assertEquals(1, clicks) }
        rule.onNodeWithTag("save_label", useUnmergedTree = true)
            .assertExists()
    }
}
```

병합된 트리에서 동작을 제공하는 노드는 구성요소가 테스트에 공개하는 계약으로 검토하세요. 구조 자체를 확인해야 할 때는 병합되지 않은 트리에서 자식 노드를 조회하세요. 자식 태그가 병합된 트리에 드러난다고 가정하지 마세요. 두 트리가 다르면 `clearAndSetSemantics`와 중첩된 상호작용 노드를 확인하세요. 접근성 서비스는 병합되지 않은 트리에 자체 병합 규칙을 적용하므로 TalkBack은 별도로 검증하세요. 스크린샷이 비슷하다는 사실만으로 시맨틱을 검증할 수는 없습니다.

테스트를 실행하고 Logcat에 출력된 두 트리를 비교하세요. 음성 대조군으로 자식의 태그를 제거한 뒤 구조 단언이 실패하는 동안 해당 동작은 여전히 사용할 수 있는지 확인하세요. 이 결과는 예상이며 계측 테스트와 TalkBack 검증은 **실행하지 않았습니다**.

핵심 시맨틱·테스트 API와 Foundation의 `Row`는 Compose 1.0.0부터 제공됩니다. Material3의 `Button`과 `Text`는 1.0.0부터 제공됩니다. 기준은 UI/Foundation/Runtime/UI Test 1.13.0과 Material3 1.5.0 안정 버전이며 컴파일하지 않았습니다. API별 AGP 최소 버전이나 실험 기능 옵트인은 없습니다. AGP 9.5 전용 기능도 사용하지 않았습니다. 이 기준 버전을 사용할 때는 실제로 해석된 AAR 메타데이터, compileSdk 37.1, Kotlin 컴파일러 2.2와 이에 맞는 Compose 컴파일러 플러그인을 확인하세요. Gradle과 JDK는 선택한 AGP에 따라 달라집니다. AGP 9.2 문서에는 Gradle 9.4.1과 JDK 17이 명시되어 있고 API는 37.0까지만 지원합니다. 이 글에서는 37.1 호환성을 확인하지 않았습니다.
