## 출시 확인(2026-11-24, Asia/Seoul)

**공식 출시 목록에서 직전 24시간(2026-11-23~2026-11-24) 동안 새 Compose 그룹 출시를 찾지 못했습니다.** 이 확인만으로 해당 기간에 AndroidX 커밋이 없었다고 판단할 수는 없습니다. 목록에 기록된 최신 출시일은 **2026-11-18**입니다. UI/Foundation/Runtime/Animation은 **1.13.0 안정 버전**, **1.14.0-alpha01**, Material3는 **1.5.0 안정 버전**, **1.6.0-alpha01**입니다. 새 BOM 리비전과 도구, 접근성, UI 테스트 관련 커밋 내역은 별도로 전수 확인하지 않았습니다.

## 실전 팁 — 자주 달라지는 배치에 람다 오프셋 사용하기

**문제.** 컴포지션에서 수정자를 만들면서 빠르게 바뀌는 위치 상태를 읽으면 불필요한 컴포지션 작업이 생길 수 있습니다. Compose는 상태 읽기를 배치 시점까지 미루는 오프셋 오버로드를 제공합니다. 효과는 오프셋 사용 방식에 따라 다르므로 실제 프레임 성능을 측정하세요.

예제는 재사용 가능한 컴포저블 전체를 담고 있습니다. Activity나 자동화 테스트는 포함하지 않습니다.

```kotlin
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.offset
import androidx.compose.foundation.layout.size
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.foundation.layout.Column
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableIntStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.IntOffset
import androidx.compose.ui.unit.dp

@Composable
fun DeferredOffsetExample() {
    var offsetPx by remember { mutableIntStateOf(0) }

    Column {
        Button(onClick = { offsetPx += 10 }) {
            Text("Move 10 px")
        }
        Box(
            modifier = Modifier
                .size(64.dp)
                .offset { IntOffset(x = offsetPx, y = 0) }
                .background(Color.Blue)
        )
    }
}
```

람다 오버로드는 `IntOffset`으로 **물리 픽셀** 단위의 값을 받고, `offset(x = 10.dp)`는 dp 단위의 값을 받습니다. 두 방식 모두 배치를 바꾸며, 부모의 측정 제약 조건과 자식을 위해 확보한 레이아웃 공간은 그대로 유지합니다. 람다는 레이아웃의 배치 단계에서 `offsetPx`를 읽으므로 이 읽기로 인해 컴포지션이 무효화되는 일을 피할 수 있습니다. 버튼이나 다른 읽기 지점에서는 여전히 리컴포지션이 발생할 수 있습니다.

**재현·디버깅·검토**

- [ ] 밀도와 정수 반올림 조건을 맞춘 뒤 람다 방식과 `Modifier.offset(x = (offsetPx / density).dp)`를 비교합니다. 변환 실수를 피하려면 고정 dp 값을 사용하는 별도 예제를 권장합니다.
- [ ] Layout Inspector 또는 Compose 추적을 사용해 컴포지션, 측정, 배치 작업을 구분합니다. 리컴포지션 횟수만으로 프레임 수나 성능을 판단하지 않습니다.
- [ ] 터치 영역과 형제 요소 간 겹침을 확인합니다. 오프셋을 적용해도 부모가 확보한 공간은 유지됩니다.
- [ ] RTL 동작을 확인합니다. `offset`은 레이아웃 방향을 따릅니다. 방향과 무관한 이동이 필요할 때만 `absoluteOffset`을 사용합니다.
- [ ] 애니메이션에서는 그래픽 레이어 이동과 비교하고 수정자 적용 방식을 바꾸기 전에 시맨틱과 히트 테스트를 확인합니다.
- [ ] 대상 밀도에서 성능을 측정하고 스크린샷을 캡처합니다. **이 글을 작성하면서 빌드, 추적, 스크린샷 캡처, 벤치마크를 실행하지 않았습니다.**

## 추가 팁(2026-11-24 오후) — 저장 가능한 상태의 복원 테스트하기

리컴포지션 테스트만으로는 UI가 재생성된 후 상태가 유지되는지 확인할 수 없습니다. `StateRestorationTester`로 로컬 저장 가능 상태 레지스트리를 테스트하세요. 다음은 계측 테스트 클래스 전체입니다. Compose를 사용하는 Android 모듈에 JUnit4, `ui-test-junit4`, 디버그용 `ui-test-manifest`, Material3가 필요합니다.

```kotlin
import androidx.compose.material3.Button
import androidx.compose.material3.Text
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.saveable.rememberSaveable
import androidx.compose.runtime.setValue
import androidx.compose.ui.test.assertIsDisplayed
import androidx.compose.ui.test.junit4.StateRestorationTester
import androidx.compose.ui.test.junit4.createComposeRule
import androidx.compose.ui.test.onNodeWithText
import androidx.compose.ui.test.performClick
import org.junit.Rule
import org.junit.Test

class SaveableCounterTest {
    @get:Rule
    val rule = createComposeRule()

    @Test
    fun counterSurvivesRestoration() {
        val tester = StateRestorationTester(rule)
        tester.setContent {
            var count by rememberSaveable { mutableStateOf(0) }
            Button(onClick = { count++ }) {
                Text("Count: $count")
            }
        }
        rule.onNodeWithText("Count: 0").performClick()
        rule.onNodeWithText("Count: 1").assertIsDisplayed()
        tester.emulateSavedInstanceStateRestore()
        rule.onNodeWithText("Count: 1").assertIsDisplayed()
    }
}
```

- 음성 대조군으로 `rememberSaveable`을 `remember`로 바꿉니다. 마지막 단언이 실패해야 합니다.
- 실제 Activity 재생성, 화면 회전, 프로세스 종료는 별도로 테스트합니다. 이 테스터는 로컬 저장 상태 복원을 확인합니다.
- 저장 상태 `Bundle`에는 작은 UI 상태나 식별자를 저장합니다. 큰 모델은 저장하지 않습니다.
- 적응형 레이아웃 전환은 상태 복원과 별도로 검증합니다.

`StateRestorationTester`, `rememberSaveable`, 핵심 테스트 API는 Compose 1.0.0부터 제공됩니다. Material3의 `Button`과 `Text`는 1.0.0부터 제공됩니다. 기준 버전은 UI Test/Runtime 1.13.0과 Material3 1.5.0 안정 버전입니다. 컴파일하거나 실행하지 않았습니다. API별 AGP 최소 버전이나 실험 기능 옵트인은 없습니다. 실제로 해석된 AAR 메타데이터와 compileSdk 37.1, 호환 AGP를 확인하세요. AGP 9.2는 API 37.0까지만 지원합니다(Gradle 9.4.1, JDK 17). Runtime 1.13에는 Kotlin 컴파일러 2.2가 필요합니다. Kotlin 버전에 맞는 Compose 컴파일러 플러그인을 사용하세요. AGP 9.5의 실험 기능은 필요하지 않습니다. 계측 테스트, 음성 대조군, 실제 재생성 테스트는 **실행하지 않았습니다**.

[상태 복원 가이드](https://developer.android.com/develop/ui/compose/state-saving), [StateRestorationTester API](https://developer.android.com/reference/kotlin/androidx/compose/ui/test/junit4/StateRestorationTester), [AGP 9.2](https://developer.android.com/build/releases/agp-9-2-0-release-notes), [Runtime 출시 목록](https://developer.android.com/jetpack/androidx/releases/compose-runtime)을 참고하세요.

오후에 공식 출시 목록을 다시 확인했을 때도 최신 Compose 그룹 출시일은 11월 18일이었습니다. 직전 24시간 동안 새 그룹 출시는 확인되지 않았습니다. 11월 18일에 나온 Runtime 1.14.0-alpha01은 중첩 스냅샷에서 부모 스냅샷을 전진시키는 동작을 바꾸고, `Snapshot.readOnly`를 추가하고, `MutableVector`를 지원 중단 예정으로 지정해 `androidx.collection.MutableObjectList` 사용을 권장합니다. 이 변경사항은 알파 버전에 해당하며 새 안정 버전 출시는 확인되지 않았습니다. 정확한 BOM 리비전과 개별 소스 커밋은 확인하지 못했습니다.
