## 새 소식: Runtime 1.13.0 Stable (2026-11-18)

Compose Runtime **1.13.0 stable**에서 `computedStateOf { }`가 소개되었습니다. `derivedStateOf`는 계산 결과를 캐싱하지만, `computedStateOf`는 **value를 읽을 때마다 계산**합니다. 계산이 가볍고 한 프레임에서 반복해서 읽지 않는 경우 캐싱 비용을 줄이는 선택지가 됩니다. 모든 상황에서 빠르다는 뜻은 아닙니다.

같은 날 Compose UI/Foundation/Animation **1.13.0 stable**, Material3 **1.5.0 stable** 및 다음 alpha(UI 등 1.14.0-alpha01, Material3 1.6.0-alpha01)가 릴리스 목록에 나타납니다. **11월 19일~20일 오전의 추가 신규 릴리스는 공식 목록에서 확인되지 않았습니다.**

## 1. 계산 비용과 읽기 빈도를 함께 리뷰하기

아래는 독립적으로 복사 가능한 Kotlin Composable 예제입니다.

~~~kotlin
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.computedStateOf
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableIntStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

@Composable
fun ComputedCounterLabel() {
    var count by remember { mutableIntStateOf(0) }
    val parity = remember { computedStateOf { count % 2 == 0 } }
    Text(if (parity.value) "Even" else "Odd")
}
~~~

위 예제는 상태 계산과 UI 출력만 설명하며 **count를 변경하는 버튼은 포함하지 않습니다**. 실제 갱신을 재현하려면 사용자 입력으로 count를 증가시키는 테스트 UI를 추가하세요. `computedStateOf`는 상태를 읽을 때 계산되므로 결과를 여러 번 읽거나 무거운 계산·객체 할당이 포함된 경우에는 `derivedStateOf`의 캐싱이 유리할 수 있습니다.

**코드 리뷰 체크:** [ ] 동일 프레임 반복 읽기 횟수 [ ] 계산 블록의 객체 할당/알고리즘 비용 [ ] 결과 객체 identity 의존성 [ ] 결과 변화에 따른 recomposition 범위 [ ] 벤치마크 없이 무조건 성능 향상이라고 단정하지 않았는가?

## 2. 계산 람다에서 State 쓰기 금지

Runtime **1.13.0-beta01부터** `computedStateOf` 계산 블록 안에서 상태를 변경하면 `IllegalStateException`이 발생합니다. 계산 람다는 순수한 읽기 중심으로 유지하고, 상태 변경은 이벤트 처리나 적절한 effect에서 수행하세요.

~~~kotlin
import androidx.compose.runtime.Composable
import androidx.compose.runtime.computedStateOf
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableIntStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

@Composable
fun ReadOnlyCalculation() {
    var source by remember { mutableIntStateOf(3) }
    val doubled = remember { computedStateOf { source * 2 } }
    androidx.compose.material3.Text("Result: ${doubled.value}")
}
~~~

**디버깅:** 계산 람다 안에 `source++`, `state.value = ...` 등이 없는지 확인하세요. `Snapshot.withoutReadObservation`을 쓰는 경로는 Runtime 1.13.0-beta02의 invalidation 수정과 연관되므로 버전 업그레이드 후 회귀 테스트를 권장합니다.

## 버전 및 도구 요구사항

| 항목 | 적용 및 확인 |
| --- | --- |
| API 최초 도입 | `computedStateOf`: Runtime 1.13.0 계열에서 도입, **stable 1.13.0** 기준 작성. 정확한 최초 alpha 빌드는 별도 확인 필요 |
| 예제 기준 | Runtime 1.13.0, Material3 1.5.0; **빌드/테스트 미실행** |
| 안정화 수준 | 1.13.0 stable (2026-11-18); 실험적 LinkComposer/SlotTable 최적화와 구분 |
| AGP / compileSdk | Runtime 1.12.0-alpha01 릴리스 노트에 **compileSdk 37 / AGP 9.2.0+** 명시. API 자체에 별도 AGP 최소 요건 없음 |
| Kotlin / Compiler | Runtime 1.13.0-beta01부터 **Kotlin compiler 2.2 필요**. Kotlin 2.x Compose Compiler Gradle plugin은 Kotlin 버전에 맞춰 설정 |
| JDK / minSdk | 프로젝트의 AGP/AndroidX artifact 요구사항에 따름; 이 예제만의 독립된 최소값은 검증하지 않음 |
| 실험적 API | 위 `computedStateOf` 예제에 별도 opt-in 사용하지 않음; LinkComposer는 별도 opt-in |

AGP 9.1만으로 최신 Compose 1.13을 지원한다고 가정하지 마세요. 최신 AndroidX artifact의 compileSdk 요구사항과 실제 프로젝트의 AGP 호환성을 함께 확인해야 합니다. AGP 9.5+ 실험적 screenshot Test Suites는 이번 예제에 필요하지 않습니다.
