> **API availability.** The official API reference marks the Runtime API `computedStateOf` as **Added in 1.13.0-rc01**. Using it requires a newer version than stable 1.12. Check the prerelease's Kotlin, AGP, and compileSdk requirements as well.

## 1. `computedStateOf` vs. `derivedStateOf`

Both APIs let consumers observe changes to the resulting value of derived state. `computedStateOf` recalculates on each read, and `derivedStateOf` caches the result.

### Inexpensive calculations with `computedStateOf` (1.13.0 RC+)

~~~kotlin
import androidx.compose.foundation.lazy.rememberLazyListState
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.computedStateOf
import androidx.compose.runtime.getValue
import androidx.compose.runtime.remember

@Composable
fun ComputedScrollStatus() {
    val listState = rememberLazyListState()
    val showButton by remember(listState) {
        computedStateOf { listState.firstVisibleItemIndex > 0 }
    }
    Text(if (showButton) "위로 이동" else "첫 항목")
}
~~~

This example has the same intent as the abbreviated `remember { computedStateOf { ... } }` example from the earlier session. Here, `listState` is an explicit key. When an input changes and the output stays the same, the API can reduce unnecessary updates to subscribed Composition. Each read can still incur the calculation cost. Keep the calculation block free of state writes and other side effects.

### More expensive calculations with `derivedStateOf` (1.0.0+)

~~~kotlin
import androidx.compose.runtime.Composable
import androidx.compose.runtime.State
import androidx.compose.runtime.derivedStateOf
import androidx.compose.runtime.remember

@Composable
fun rememberFilteredCount(numbers: State<List<Int>>): State<Int> =
    remember(numbers) {
        derivedStateOf { numbers.value.count { it > 100 } }
    }
~~~

This calculation can grow more expensive in proportion to the size of the list, so caching the result may help. Measure to determine whether the calculation is a bottleneck and avoid allocating excessive derived state objects.

**Versions and AGP.** `computedStateOf` requires **Runtime 1.13.0-rc01+ (RC)**. `derivedStateOf` is available in **Runtime 1.0.0+**. Projects using Compose 1.13 with `computedStateOf` should check the **AGP 9.0+ and compileSdk 37** baseline and the Kotlin requirements of their specific 1.13 release. The older API has no separate minimum AGP version. **Verification.** The API contracts were checked. The examples have yet to be built in an app.

**Official references.** [Runtime package summary](https://developer.android.com/reference/kotlin/androidx/compose/runtime/package-summary) · [Compose performance guide](https://developer.android.com/develop/ui/compose/performance)

## 2. Read animation state in the draw phase with `graphicsLayer`

**Before.** Reading an animated value during composition can rerun the subscribing Composition on every frame.

~~~kotlin
import androidx.compose.animation.core.animateFloatAsState
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.size
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.ui.Modifier
import androidx.compose.ui.draw.alpha
import androidx.compose.ui.unit.dp

@Composable
fun FadeBefore(targetAlpha: Float) {
    val alpha by animateFloatAsState(
        targetValue = targetAlpha,
        label = "alpha"
    )
    Box(Modifier.size(48.dp).alpha(alpha))
}
~~~

**After.** Move the `State.value` read inside the `graphicsLayer` block.

~~~kotlin
import androidx.compose.animation.core.animateFloatAsState
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.size
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.graphicsLayer
import androidx.compose.ui.unit.dp

@Composable
fun FadeAfter(targetAlpha: Float) {
    val animatedAlpha = animateFloatAsState(
        targetValue = targetAlpha,
        label = "alpha"
    )
    Box(
        Modifier.size(48.dp).graphicsLayer {
            alpha = animatedAlpha.value
        }
    )
}
~~~

**Observation.** Since this state read happens during the draw phase, changes to the value can update drawing without rerunning composition or layout. Check GPU layer and compositing costs separately, along with other reads of the same state.

### Defer state reads to layout placement with `offset { }`

~~~kotlin
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.size
import androidx.compose.runtime.Composable
import androidx.compose.runtime.State
import androidx.compose.ui.Modifier
import androidx.compose.foundation.layout.offset
import androidx.compose.ui.unit.IntOffset
import androidx.compose.ui.unit.dp

@Composable
fun MovingBox(offsetPx: State<Int>) {
    Box(
        Modifier.size(48.dp)
            .offset { IntOffset(0, offsetPx.value) }
    )
}
~~~

This lambda returns an `IntOffset` in **pixels**. If a position change affects only placement, deferring the read to placement can be more efficient than reading the state during composition.

**Versions and AGP.** The examples use Compose UI and Animation APIs in the **1.0.0+** families for `Modifier.graphicsLayer`, `Modifier.offset { }`, `Modifier.alpha`, and `animateFloatAsState`. Check which overloads are available in your version. The APIs have no separate minimum AGP version. Compose 1.12.0+ requires **AGP 9.0+ and compileSdk 37**. **Performance has yet to be measured.**

**Official references.** [Modifier phases](https://developer.android.com/develop/ui/compose/performance/modifier-phases) · [Compose practical performance codelab](https://developer.android.com/codelabs/jetpack-compose-performance)

## 3. `LaunchedEffect` keys and `rememberUpdatedState`

A timer that waits while a screen is active can often keep running when only the callback object changes.

~~~kotlin
import androidx.compose.runtime.Composable
import androidx.compose.runtime.LaunchedEffect
import androidx.compose.runtime.getValue
import androidx.compose.runtime.rememberUpdatedState
import kotlinx.coroutines.delay

@Composable
fun TimeoutEffect(
    timeoutMs: Long,
    onTimeout: () -> Unit
) {
    val latestOnTimeout by rememberUpdatedState(onTimeout)

    // timeoutMs가 바뀔 때만 타이머 재시작
    LaunchedEffect(timeoutMs) {
        delay(timeoutMs)
        latestOnTimeout()
    }
}
~~~

`rememberUpdatedState(onTimeout)` allows the effect to read the **current callback without restarting**. A change to `timeoutMs`, the key, cancels the previous coroutine and starts a new delay. The effect also runs during initial composition.

**Review.** Check for missing key inputs, whether a callback change should restart the timer, and whether automatic cancellation when the composable leaves the Composition is appropriate.

**Versions and AGP.** `LaunchedEffect` and `rememberUpdatedState` are available in the Compose Runtime 1.0.0+ family. They have no separate minimum AGP version and follow the toolchain requirements of the Compose dependency you adopt. **Verification.** Checked against the behavior described by the official sample. Execution tests have yet to run.
