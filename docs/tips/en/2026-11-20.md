## Release update for Runtime 1.13.0 stable (2026-11-18)

Compose Runtime **1.13.0 stable** introduces `computedStateOf { }`. `derivedStateOf` caches calculation results. `computedStateOf` **calculates the result on every read of value**. When the calculation is cheap and reads are infrequent within a frame, this can reduce caching overhead. Performance depends on the workload.

The same date's release listings include Compose UI, Foundation, and Animation **1.13.0 stable**, Material 3 **1.5.0 stable**, and the next alpha versions (1.14.0-alpha01 for libraries including UI, 1.6.0-alpha01 for Material 3). **The official listings showed no additional releases from November 19 through the morning of November 20.**

## 1. Review calculation cost and read frequency together

You can copy this self-contained Kotlin composable.

~~~kotlin
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.computedStateOf
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableIntStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

@Composable
fun ComputedCounterLabel() {
    var count by remember { mutableIntStateOf(0) }
    val parity = remember { computedStateOf { count % 2 == 0 } }
    Text(if (parity.value) "Even" else "Odd")
}
~~~

The example shows state calculation and UI output only. To reproduce an update, add a test UI with a button that increments `count`. Because `computedStateOf` calculates the result when the state is read, `derivedStateOf` caching may help when the result is read multiple times or the calculation does expensive work or allocates objects.

**Code review.** [ ] Number of repeat reads in the same frame [ ] Object allocations and algorithm cost of the calculation [ ] Dependence on result object identity [ ] Recomposition scope when the result changes [ ] Benchmark evidence for any performance claims.

## 2. Keep calculation lambdas read-only

Starting with Runtime **1.13.0-beta01**, writing to state in a `computedStateOf` calculation block throws `IllegalStateException`. Keep the calculation lambda pure and read-only. Change state in event handlers or an appropriate effect.

~~~kotlin
import androidx.compose.runtime.Composable
import androidx.compose.runtime.computedStateOf
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableIntStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

@Composable
fun ReadOnlyCalculation() {
    var source by remember { mutableIntStateOf(3) }
    val doubled = remember { computedStateOf { source * 2 } }
    androidx.compose.material3.Text("Result: ${doubled.value}")
}
~~~

**Debugging.** Check the calculation lambda for writes such as `source++` or `state.value = ...`. Paths using `Snapshot.withoutReadObservation` are affected by the invalidation fix in Runtime 1.13.0-beta02. Run regression tests after upgrading.
