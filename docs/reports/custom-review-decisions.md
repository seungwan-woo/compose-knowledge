# Custom Compose delivery decisions

These controller decisions follow the reference-only privacy requirement. They preserve the chosen limits and costs for review; they are not evidence of unobserved failures. The original decision-order record is retained in the separate audit. See the [acceptance results](custom-review-acceptance.md).

1. Use an isolated reversible worktree without another approval round; do not change/publish environment configuration. If isolation is insufficient, integration work could overlap existing branches; the original checkout was preserved.

2. Supersede the earlier private manifest/graph importer with direct consumer-local inspection under an approved agent deployment. Cost: local relationship context is supplied by the consumer agent instead of automatically indexed here.

3. Deliver begin/route/lookup, selected contracts, compact instructions and the frozen six-case pilot. Defer the proposed 28-case breadth. Cost: results do not establish broad or unseen-topic effectiveness.

4. Use manual file briefs, diff packages and the ignored task ledger because the optional SDD helper resource was unavailable. Cost: the controller maintains audit linkage manually.

5. Keep one tracked-file implementer at a time; parallelize independent research, preparation, reviews and consumer cases. Cost: some implementation stages wait for review, avoiding shared-file races.

6. Allow one-time first-lookup version binding after initial sync and local version inspection. Cost: one optional flag path and validation; context still freezes before retrieval.

7. Set the pack ceiling to remaining 12,288 bytes rather than 6,144, because the complete AndroidView contract exceeds the smaller ceiling. Cost: one call can consume more context, but output remains selected and the whole-task limit is unchanged.

8. Preserve fail-closed required-source acquisition and attach affected-span needs-review statuses to failure reports. Cost: one required source outage blocks publication rather than producing a partial snapshot.

9. Honor preferred route cards only within normal query/artifact/version eligibility; retain ordinary fallback. Cost: a bounded preference query adds local retrieval work; it cannot substitute arbitrary IDs or versions.

10. Choose legacy manual retrieval upfront for topics outside the eight pack families; prohibit workflow switching after lookup. Cost: two explicit workflows remain, and legacy budget accounting is manual.

11. Ambiguous aliases spend one attempt and navigation-envelope bytes but emit no evidence sections. Cost: one refinement may be necessary; it preserves the second attempt's complete-pack capacity.

12. Failed loaded-task lookups persist the spent attempt/freeze, while newly supplied versions commit only with successful output. Cost: a failed first call can retain unknown versions for the remaining attempt; retries cannot rewrite context.

13. Preserve the failed six-case cohort and retest only the two observed failure paths with fresh agents, a separate bundle and corrected harness. Cost: the selective retest is not a new full six-case savings or holdout result.

14. Use the existing implementation/PR authorization to open a reviewable feature draft PR without another permission menu. Cost: reviewed public/generic changes become visible on a feature branch; no main merge or environment/corpus publication is included.

15. Implement the documented public remote default for new begin, preserving explicit approved-mirror precedence and legacy sync behavior. Cost: omitted remote contacts the public corpus; corporate or offline deployments must configure their approved remote or offline mode.

No public corpus/environment publication, merge, consumer Android build, private import or provider-billing measurement is part of this delivery. New-source released applicability stays unknown until the consumer supplies verified dependency facts.
