      ## 1. `derivedStateOf`: 자주 바뀌는 스크롤 상태에서 Boolean만 갱신

      스크롤의 픽셀 오프셋은 자주 바뀌지만, **최상단 복귀 버튼을 보여줄지**는 아이템 인덱스가 0에서 벗어날 때만 변경되면 됩니다.

      ~~~kotlin
      import androidx.compose.foundation.lazy.LazyColumn
      import androidx.compose.foundation.lazy.items
      import androidx.compose.foundation.lazy.rememberLazyListState
      import androidx.compose.material3.Text
      import androidx.compose.runtime.Composable
      import androidx.compose.runtime.derivedStateOf
      import androidx.compose.runtime.getValue
      import androidx.compose.runtime.remember

      @Composable
      fun ShowTopStatus() {
          val listState = rememberLazyListState()
          val showTopButton by remember(listState) {
              derivedStateOf { listState.firstVisibleItemIndex > 0 }
          }

          // Button/AnimatedVisibility의 표시 조건으로도 사용할 수 있습니다.
          Text(if (showTopButton) "맨 위로 이동 가능" else "목록 첫 항목")
          LazyColumn(state = listState) {
              items((1..100).toList()) { index ->
                  Text("Item $index")
              }
          }
      }
      ~~~

      **의도:** 변하는 입력을 읽고 실제 출력 Boolean이 달라졌을 때만 이를 구독하는 UI를 갱신하는 데 활용합니다. `derivedStateOf` 계산 결과는 캐시되지만 계산 비용이 없는 문자열 결합까지 모두 감싸는 것은 오히려 과도할 수 있습니다. 위 목록의 버튼 구현은 설명을 위해 텍스트로 대체했습니다.

      **코드 리뷰:** `remember`의 key가 올바른지, `derivedStateOf` 계산 안에서 상태를 변경하지 않는지, 실제 Composition이 `showTopButton`을 관찰하는지 확인하세요.

      **적용 범위:** `derivedStateOf` — `androidx.compose.runtime:runtime:1.0.0+`. `LazyColumn`은 Foundation, `Text`는 Material3 의존성 필요. **AGP:** API 자체의 별도 AGP 최소 조건 없음. 그러나 Compose 1.12.0 이상으로 올리는 프로젝트는 공식 요구대로 **AGP 9.0+ / compileSdk 37**이 필요합니다.

      **공식 근거:** [Runtime API](https://developer.android.com/reference/kotlin/androidx/compose/runtime/package-summary) · [Compose Performance best practices](https://developer.android.com/develop/ui/compose/performance/bestpractices)

      ## 2. Compose BOM은 라이브러리 버전 묶음; Compiler는 별도

      이전 브리핑의 `alias(libs.plugins.kotlin.compose)` 및 `implementation(platform(...))` 예제는 Version Catalog가 있는 프로젝트에서 적용 가능합니다. 아래는 독립적인 **부분 설정 예시**입니다.

      `gradle/libs.versions.toml` 예시(버전은 현재 프로젝트가 실제 채택한 조합으로 고정):

      ~~~toml
      [versions]
      kotlin = "2.2.20"
      composeBom = "2026.09.00"

      [plugins]
      kotlin-compose = { id = "org.jetbrains.kotlin.plugin.compose", version.ref = "kotlin" }

      [libraries]
      androidx-compose-bom = { module = "androidx.compose:compose-bom", version.ref = "composeBom" }
      ~~~

      모듈의 `build.gradle.kts` 부분 예시:

      ~~~kotlin
      plugins {
          // Android 및 Kotlin 플러그인은 프로젝트 설정에 따라 별도 선언.
          alias(libs.plugins.kotlin.compose)
      }

      android {
          buildFeatures { compose = true }
      }

      dependencies {
          val composeBom = platform(libs.androidx.compose.bom)
          implementation(composeBom)
          androidTestImplementation(composeBom)

          implementation("androidx.compose.ui:ui")
          implementation("androidx.compose.foundation:foundation")
          implementation("androidx.compose.material3:material3")

          androidTestImplementation("androidx.compose.ui:ui-test-junit4")
      }
      ~~~

      `Compose BOM`은 라이브러리 그룹 간 버전 정합성을 조율합니다. **Compose Compiler를 포함하지 않습니다.** Kotlin 2.0 이상에서는 `org.jetbrains.kotlin.plugin.compose` 플러그인을 Kotlin과 같은 버전으로 사용합니다. BOM을 올리는 것만으로 Kotlin/Compiler/AGP까지 자동 교체되는 것은 아닙니다.

      **적용 범위:** 위 예시의 BOM `2026.09.00`은 공식 문서에 명시된 예시 버전이며 이 날짜에서 모든 artifact의 최신이라고 단정하지 않습니다. `kotlin = "2.2.20"`은 설명용 버전이므로 실제 프로젝트의 Kotlin 및 AGP 호환성 확인이 필요합니다. **AGP:** BOM 자체가 AGP 버전을 관리하지 않음. **Compose 1.12.0+ 라이브러리 사용 시 AGP 9.0+ / compileSdk 37**; `1.13` 계열은 Kotlin 컴파일러 요구사항도 릴리스 노트로 확인하세요. **검증:** 예시 설정의 Gradle sync/빌드 미실행.

      **공식 근거:** [BOM 안내](https://developer.android.com/develop/ui/compose/bom) · [BOM 매핑](https://developer.android.com/develop/ui/compose/bom/bom-mapping) · [Compose compiler와 AGP 요구사항](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)

## 1. `derivedStateOf`: 자주 바뀌는 스크롤 상태에서 Boolean만 갱신

import androidx.compose.runtime.Composable

import androidx.compose.runtime.remember

@Composable

## 2. Compose BOM은 라이브러리 버전 묶음; Compiler는 별도

이전 브리핑의 `alias(libs.plugins.kotlin.compose)` 및 `implementation(platform(...))` 예제는 Version Catalog가 있는 프로젝트에서 적용 가능합니다. 아래는 독립적인 **부분 설정 예시**입니다.

`gradle/libs.versions.toml` 예시(버전은 현재 프로젝트가 실제 채택한 조합으로 고정):

~~~toml
[versions]
kotlin = "2.2.20"
composeBom = "2026.09.00"

[plugins]
kotlin-compose = { id = "org.jetbrains.kotlin.plugin.compose", version.ref = "kotlin" }

[libraries]
androidx-compose-bom = { module = "androidx.compose:compose-bom", version.ref = "composeBom" }
~~~

모듈의 `build.gradle.kts` 부분 예시:

~~~kotlin
plugins {
    // Android 및 Kotlin 플러그인은 프로젝트 설정에 따라 별도 선언.
    alias(libs.plugins.kotlin.compose)
}

android {
    buildFeatures { compose = true }
}

dependencies {
    val composeBom = platform(libs.androidx.compose.bom)
    implementation(composeBom)
    androidTestImplementation(composeBom)

    implementation("androidx.compose.ui:ui")
    implementation("androidx.compose.foundation:foundation")
    implementation("androidx.compose.material3:material3")

    androidTestImplementation("androidx.compose.ui:ui-test-junit4")
}
~~~

`Compose BOM`은 라이브러리 그룹 간 버전 정합성을 조율합니다. **Compose Compiler를 포함하지 않습니다.** Kotlin 2.0 이상에서는 `org.jetbrains.kotlin.plugin.compose` 플러그인을 Kotlin과 같은 버전으로 사용합니다. BOM을 올리는 것만으로 Kotlin/Compiler/AGP까지 자동 교체되는 것은 아닙니다.

**적용 범위:** 위 예시의 BOM `2026.09.00`은 공식 문서에 명시된 예시 버전이며 이 날짜에서 모든 artifact의 최신이라고 단정하지 않습니다. `kotlin = "2.2.20"`은 설명용 버전이므로 실제 프로젝트의 Kotlin 및 AGP 호환성 확인이 필요합니다. **AGP:** BOM 자체가 AGP 버전을 관리하지 않음. **Compose 1.12.0+ 라이브러리 사용 시 AGP 9.0+ / compileSdk 37**; `1.13` 계열은 Kotlin 컴파일러 요구사항도 릴리스 노트로 확인하세요. **검증:** 예시 설정의 Gradle sync/빌드 미실행.

**공식 근거:** [BOM 안내](https://developer.android.com/develop/ui/compose/bom) · [BOM 매핑](https://developer.android.com/develop/ui/compose/bom/bom-mapping) · [Compose compiler와 AGP 요구사항](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler)
