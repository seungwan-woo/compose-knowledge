      ## Practical tip: keyed SideEffect

      Use the keyed overload when publishing a synchronous value to a non-Compose object after successful composition, only on entry or a key change. Unlike LaunchedEffect it does not launch a coroutine; unlike DisposableEffect it does not provide cleanup. Unlike unkeyed SideEffect it need not run on every successful recomposition of its call site.

      Complete reusable composable and plain Kotlin sink (not a complete Activity):

      ```kotlin
      import androidx.compose.runtime.Composable
      import androidx.compose.runtime.SideEffect

      class SelectionSink {
          var selectedId: Long? = null
              private set

          fun publish(id: Long) {
              selectedId = id
          }
      }

      @Composable
      fun PublishSelection(selectedId: Long, sink: SelectionSink) {
          SideEffect(selectedId, sink) {
              sink.publish(selectedId)
          }
      }
      ```

      Keep the sink stable across unrelated recompositions. Include the sink in the keys so replacement receives the current selection. Keep the operation short and non-blocking; use LaunchedEffect for suspending work and DisposableEffect for registration requiring cleanup. This is not a durable exactly-once event delivery mechanism: leaving and re-entering composition can publish again.

      import androidx.compose.ui.test.printToLog

      import org.junit.Assert.assertEquals
      import org.junit.Rule
      import org.junit.Test

      class MergedSemanticsTest {
          @get:Rule
          val rule = createComposeRule()

          @Test
          fun actionAndChildSemantics() {
              var clicks = 0
              rule.setContent {
                  Button(
                      onClick = { clicks++ },
                      modifier = Modifier.testTag("save_action")

                      Row {
                          Text("Save", Modifier.testTag("save_label"))
