      ### 문제 코드 — 테마 값을 처음 한 번만 기억

      ~~~kotlin
      import androidx.compose.foundation.isSystemInDarkTheme
      import androidx.compose.material3.Text
      import androidx.compose.runtime.Composable
      import androidx.compose.runtime.getValue
      import androidx.compose.runtime.mutableStateOf
      import androidx.compose.runtime.remember
      import androidx.compose.ui.graphics.Color

      @Composable
      fun StaleThemeLabel() {
          val dark = isSystemInDarkTheme()
          val textColor by remember {
              mutableStateOf(if (dark) Color.White else Color.Black)
          }
          Text("Status", color = textColor)
      }
      ~~~

      <code>remember</code> 초기화 람다는 같은 Composition에서 key가 바뀌지 않는 한 재실행되지 않습니다. **재구성(Recomposition)과 상태 초기화는 다릅니다.**

      ### 개선 코드 — 테마에서 직접 파생

      ~~~kotlin
      import androidx.compose.foundation.isSystemInDarkTheme
      import androidx.compose.material3.Text
      import androidx.compose.runtime.Composable
      import androidx.compose.ui.graphics.Color

      @Composable
      fun ReactiveThemeLabel() {
          val dark = isSystemInDarkTheme()
          val textColor = if (dark) Color.White else Color.Black
          Text("Status", color = textColor)
      }
      ~~~

      자체 디자인 시스템이나 Material3를 사용하는 앱에서는 하위 컴포넌트가 <code>MaterialTheme.colorScheme.onSurface</code> 같은 토큰을 읽도록 하는 것이 보통 더 적절합니다. **시스템 테마와 앱 자체 테마 선택은 다를 수 있습니다.**

      **코드 리뷰:** 테마 리소스가 <code>remember</code>, View Context, 싱글턴 또는 별도 <code>mutableStateOf</code>에 복제·캐싱됐는지 확인하세요. <code>remember(dark)</code>로 재초기화할 수도 있지만 사용자 수정 상태까지 재설정할 위험이 있습니다.

      **버전:** <code>isSystemInDarkTheme</code> (Foundation 1.0.0+), <code>remember</code> (Runtime 1.0.0+). Material3 예시는 해당 앱의 Material3 의존성이 필요합니다.

      **출처:** [isSystemInDarkTheme API](https://developer.android.com/reference/kotlin/androidx/compose/foundation/isSystemInDarkTheme.composable) · [remember API](https://developer.android.com/reference/kotlin/androidx/compose/runtime/remember.composable) · [Compose 상태 관리](https://developer.android.com/develop/ui/compose/state)

      ## 2. 스크롤 State를 Draw 단계에서 읽기

      **증상:** 스크롤 값에 따라 그림자나 오버레이만 바뀌는데, 자주 바뀌는 State를 Composition 단계에서 읽어 불필요한 재구성을 발생시킵니다.

      ~~~kotlin
      import androidx.compose.foundation.ScrollState
      import androidx.compose.foundation.layout.Box
      import androidx.compose.foundation.layout.fillMaxWidth
      import androidx.compose.foundation.layout.height
      import androidx.compose.ui.Modifier
      import androidx.compose.ui.draw.drawBehind
      import androidx.compose.ui.graphics.Color
      import androidx.compose.ui.unit.dp
      import androidx.compose.runtime.Composable

      @Composable
      fun ScrollEdgeShade(scrollState: ScrollState) {
          Box(
              modifier = Modifier
                  .fillMaxWidth()
                  .height(10.dp)
                  .drawBehind {
                      // State를 Composition이 아닌 Draw 단계에서 읽는다.
                      val overlayAlpha =
                          if (scrollState.value > 0) 0.35f else 0f
                      drawRect(Color.Black, alpha = overlayAlpha)
                  }
          )
      }
      ~~~

      <code>drawBehind</code> 안에서 읽은 상태가 변경되면 해당 Draw 작업을 무효화할 수 있으므로, **이 읽기 하나 때문에 Composition이나 Layout을 다시 수행할 필요가 없습니다.** 단, 같은 상태를 다른 Composition 코드에서도 읽고 있다면 그 부분의 재구성은 별도로 발생합니다.

      **확인 절차:** (1) Android Studio Layout Inspector에서 재구성 횟수 확인 → (2) 상태 읽기를 Draw 람다로 옮김 → (3) Macrobenchmark/Perfetto 등으로 실제 프레임 개선 확인. Draw 비용도 있으므로 무조건 빠르다고 가정하지 마세요.

      **버전:** <code>Modifier.drawBehind</code> (Compose UI 1.0.0+); 예제 작성 기준 Compose UI 1.7.8.

      **출처:** [drawBehind API](https://developer.android.com/reference/kotlin/androidx/compose/ui/draw/drawBehind.modifier) · [Compose Phase와 상태 읽기](https://developer.android.com/develop/ui/compose/phases) · [Modifier Phase](https://developer.android.com/develop/ui/compose/performance/modifier-phases)

      ## 3. 테마 변경을 스크린샷 픽셀 테스트로 확인

      **목표:** Light와 Dark의 실제 렌더링이 달라졌는지 간단한 화면에서 검증합니다. 아래 예제는 **Golden 비교가 아니라 픽셀 스모크 테스트**입니다. 전체 Golden 회귀 검사는 별도 참조 이미지와 비교 도구가 필요합니다.

      ~~~kotlin
      import androidx.compose.foundation.background
      import androidx.compose.foundation.layout.Box
      import androidx.compose.foundation.layout.size
      import androidx.compose.runtime.mutableStateOf
      import androidx.compose.ui.Modifier
      import androidx.compose.ui.graphics.Color
      import androidx.compose.ui.graphics.toPixelMap
      import androidx.compose.ui.platform.testTag
      import androidx.compose.ui.test.captureToImage
      import androidx.compose.ui.test.junit4.createComposeRule
      import androidx.compose.ui.test.onNodeWithTag
      import androidx.compose.ui.unit.dp
      import org.junit.Assert.assertEquals
      import org.junit.Rule
      import org.junit.Test

      class ThemePixelTest {
          @get:Rule val rule = createComposeRule()

          @Test fun themeStateUpdatesPixel() {
              val dark = mutableStateOf(false)
              rule.setContent {
                  Box(
                      Modifier
                          .size(48.dp)
                          .background(if (dark.value) Color.Black else Color.White)
                          .testTag("theme-surface")
                  )
              }

              val light = rule.onNodeWithTag("theme-surface")
                  .captureToImage().toPixelMap()[24, 24]
              assertEquals(Color.White, light)

              rule.runOnIdle { dark.value = true }

              val darkPixel = rule.onNodeWithTag("theme-surface")
                  .captureToImage().toPixelMap()[24, 24]
              assertEquals(Color.Black, darkPixel)
          }
      }
      ~~~

      **사용 조건:** Android Instrumentation Test (<code>androidTest</code>), JUnit4, <code>androidx.compose.ui:ui-test-junit4</code> 등 UI Test 의존성, **캡처 단말 API 26 이상**. 위 테스트는 앱의 시스템 다크 설정을 바꾸는 것이 아니라 **테스트용 State를 변경**합니다. 실제 시스템 테마/Configuration 전환 테스트는 별도 환경 제어가 필요합니다.

      **회귀 매트릭스:** Light/Dark × fontScale 1.0/1.3 × LTR/RTL × 화면 크기. UI 폰트 및 브러시 등은 픽셀 차이가 발생할 수 있으므로 전체 이미지 유사도 외에 **테두리·텍스트·색상 등 국소 영역**의 결함도 확인하세요.

      **도구 선택:** AGP 버전에 따라 테스트 방식을 제한하지 않고 도입 여부를 결정하세요. 기존 `ui-test-junit4` 방식은 테스트 대상 앱/단말이 필요하지만, AGP 9.5 이상에서는 Preview 기반의 Test Suites 통합도 검토할 수 있습니다. 후자는 현재 실험적입니다. 기존 독립형 `com.android.compose.screenshot` 플러그인은 공식 문서에서 유지보수 중단(deprecated path)을 안내합니다.

      ### AGP 9.5+ 실험적 Preview Screenshot Test Suite 예시

      **최소 요구:** `AGP 9.5.0-alpha03+`, Compose Screenshot Engine `0.0.1-alpha16+`, JDK 17+, Compose 활성화. 해당 AGP 버전을 사용하지 않는 프로젝트에는 이 DSL을 적용하지 마세요.

      `gradle.properties`:

      ~~~properties
      android.experimental.enableScreenshotTest=true
      android.experimental.testSuiteSupport=true
      ~~~

      모듈의 `build.gradle.kts` 중 `android { }` 설정 예시:

      ~~~kotlin
      android {
          testOptions {
              screenshotTests.create("screenshotTest") {
                  engineVersion = "0.0.1-alpha16"
                  // 실제 프로젝트에 존재하는 variant 이름으로 변경
                  targetVariants.add("demoDebug")
                  dependencies {
                      implementation(libs.androidx.compose.ui.tooling)
                      implementation(
                          "com.android.tools.screenshot:screenshot-validation-api:0.0.1-alpha16"
                      )
                  }
              }
          }
      }
      ~~~

      `src/screenshotTest/kotlin/...` 예시:

      ~~~kotlin
      import androidx.compose.runtime.Composable
      import androidx.compose.ui.tooling.preview.Preview
      import com.android.tools.screenshot.PreviewTest

      @PreviewTest
      @Preview(name = "light", uiMode = 0x10)
      @Preview(name = "dark", uiMode = 0x20)
      @Composable
      fun ThemePreviewTest() {
          AppTheme {
              ScreenContent()
          }
      }
      ~~~

      `AppTheme`과 `ScreenContent`는 앱이 제공하는 Composable로 교체해야 합니다. 코드 블록은 설정·핵심 API를 보여주는 **부분 예시**이며, 모듈·Gradle 프로젝트에 맞춘 통합 빌드와 Golden 생성은 별도로 진행해야 합니다. 세부 설정과 작업 이름은 [공식 Test Suites 안내](https://developer.android.com/studio/preview/compose-screenshot-testing-with-testsuites)를 확인하세요.

      **버전:** 예제 API 기준 Compose UI Test **1.7.8**; 실제 프로젝트의 UI/UI Test 버전은 일치시키고 컴파일을 검증해야 합니다. <code>captureToImage()</code>는 Android API 26+가 요구됩니다.

      **출처:** [Compose UI Test API](https://developer.android.com/reference/kotlin/androidx/compose/ui/test/SemanticsNodeInteraction) · [Screenshot 테스트 안내](https://developer.android.com/training/testing/ui-tests/screenshot) · [AGP Test Suites 기반 실험적 통합](https://developer.android.com/studio/preview/compose-screenshot-testing-with-testsuites)

## Practical Tip: 문제 코드 — 테마 값을 처음 한 번만 기억

Practical Tip: author-curated guidance, NOT an independently verified AndroidX contract.

### 문제 코드 — 테마 값을 처음 한 번만 기억

~~~kotlin
import androidx.compose.foundation.isSystemInDarkTheme
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.ui.graphics.Color

@Composable
fun StaleThemeLabel() {
    val dark = isSystemInDarkTheme()
    val textColor by remember {
        mutableStateOf(if (dark) Color.White else Color.Black)
    }
    Text("Status", color = textColor)
}
~~~

<code>remember</code> 초기화 람다는 같은 Composition에서 key가 바뀌지 않는 한 재실행되지 않습니다. **재구성(Recomposition)과 상태 초기화는 다릅니다.**

import androidx.compose.runtime.Composable
import androidx.compose.ui.graphics.Color

@Composable
fun ReactiveThemeLabel() {
    val dark = isSystemInDarkTheme()
    val textColor = if (dark) Color.White else Color.Black
    Text("Status", color = textColor)
}
~~~

자체 디자인 시스템이나 Material3를 사용하는 앱에서는 하위 컴포넌트가 <code>MaterialTheme.colorScheme.onSurface</code> 같은 토큰을 읽도록 하는 것이 보통 더 적절합니다. **시스템 테마와 앱 자체 테마 선택은 다를 수 있습니다.**

**코드 리뷰:** 테마 리소스가 <code>remember</code>, View Context, 싱글턴 또는 별도 <code>mutableStateOf</code>에 복제·캐싱됐는지 확인하세요. <code>remember(dark)</code>로 재초기화할 수도 있지만 사용자 수정 상태까지 재설정할 위험이 있습니다.

**버전:** <code>isSystemInDarkTheme</code> (Foundation 1.0.0+), <code>remember</code> (Runtime 1.0.0+). Material3 예시는 해당 앱의 Material3 의존성이 필요합니다.

**출처:** [isSystemInDarkTheme API](https://developer.android.com/reference/kotlin/androidx/compose/foundation/isSystemInDarkTheme.composable) · [remember API](https://developer.android.com/reference/kotlin/androidx/compose/runtime/remember.composable) · [Compose 상태 관리](https://developer.android.com/develop/ui/compose/state)

## 2. 스크롤 State를 Draw 단계에서 읽기

**증상:** 스크롤 값에 따라 그림자나 오버레이만 바뀌는데, 자주 바뀌는 State를 Composition 단계에서 읽어 불필요한 재구성을 발생시킵니다.

~~~kotlin
import androidx.compose.foundation.ScrollState
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.fillMaxWidth
import androidx.compose.foundation.layout.height
import androidx.compose.ui.Modifier
import androidx.compose.ui.draw.drawBehind
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.dp
import androidx.compose.runtime.Composable

@Composable
fun ScrollEdgeShade(scrollState: ScrollState) {
    Box(
        modifier = Modifier
            .fillMaxWidth()
            .height(10.dp)
            .drawBehind {
                // State를 Composition이 아닌 Draw 단계에서 읽는다.
                val overlayAlpha =
                    if (scrollState.value > 0) 0.35f else 0f
                drawRect(Color.Black, alpha = overlayAlpha)
            }
    )
}
~~~

<code>drawBehind</code> 안에서 읽은 상태가 변경되면 해당 Draw 작업을 무효화할 수 있으므로, **이 읽기 하나 때문에 Composition이나 Layout을 다시 수행할 필요가 없습니다.** 단, 같은 상태를 다른 Composition 코드에서도 읽고 있다면 그 부분의 재구성은 별도로 발생합니다.

**확인 절차:** (1) Android Studio Layout Inspector에서 재구성 횟수 확인 → (2) 상태 읽기를 Draw 람다로 옮김 → (3) Macrobenchmark/Perfetto 등으로 실제 프레임 개선 확인. Draw 비용도 있으므로 무조건 빠르다고 가정하지 마세요.

**버전:** <code>Modifier.drawBehind</code> (Compose UI 1.0.0+); 예제 작성 기준 Compose UI 1.7.8.

**출처:** [drawBehind API](https://developer.android.com/reference/kotlin/androidx/compose/ui/draw/drawBehind.modifier) · [Compose Phase와 상태 읽기](https://developer.android.com/develop/ui/compose/phases) · [Modifier Phase](https://developer.android.com/develop/ui/compose/performance/modifier-phases)

## 3. 테마 변경을 스크린샷 픽셀 테스트로 확인

**목표:** Light와 Dark의 실제 렌더링이 달라졌는지 간단한 화면에서 검증합니다. 아래 예제는 **Golden 비교가 아니라 픽셀 스모크 테스트**입니다. 전체 Golden 회귀 검사는 별도 참조 이미지와 비교 도구가 필요합니다.

~~~kotlin
import androidx.compose.foundation.background
import androidx.compose.foundation.layout.Box
import androidx.compose.foundation.layout.size
import androidx.compose.runtime.mutableStateOf
import androidx.compose.ui.Modifier
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.graphics.toPixelMap
import androidx.compose.ui.platform.testTag
import androidx.compose.ui.test.captureToImage
import androidx.compose.ui.test.junit4.createComposeRule
import androidx.compose.ui.test.onNodeWithTag
import androidx.compose.ui.unit.dp
import org.junit.Assert.assertEquals
import org.junit.Rule
import org.junit.Test

class ThemePixelTest {
    @get:Rule val rule = createComposeRule()

    @Test fun themeStateUpdatesPixel() {
        val dark = mutableStateOf(false)
        rule.setContent {
            Box(
                Modifier
                    .size(48.dp)
                    .background(if (dark.value) Color.Black else Color.White)
                    .testTag("theme-surface")
            )
        }

        val light = rule.onNodeWithTag("theme-surface")
            .captureToImage().toPixelMap()[24, 24]
        assertEquals(Color.White, light)

        rule.runOnIdle { dark.value = true }

        val darkPixel = rule.onNodeWithTag("theme-surface")
            .captureToImage().toPixelMap()[24, 24]
        assertEquals(Color.Black, darkPixel)
    }
}
~~~

**사용 조건:** Android Instrumentation Test (<code>androidTest</code>), JUnit4, <code>androidx.compose.ui:ui-test-junit4</code> 등 UI Test 의존성, **캡처 단말 API 26 이상**. 위 테스트는 앱의 시스템 다크 설정을 바꾸는 것이 아니라 **테스트용 State를 변경**합니다. 실제 시스템 테마/Configuration 전환 테스트는 별도 환경 제어가 필요합니다.

**회귀 매트릭스:** Light/Dark × fontScale 1.0/1.3 × LTR/RTL × 화면 크기. UI 폰트 및 브러시 등은 픽셀 차이가 발생할 수 있으므로 전체 이미지 유사도 외에 **테두리·텍스트·색상 등 국소 영역**의 결함도 확인하세요.

**도구 선택:** AGP 버전에 따라 테스트 방식을 제한하지 않고 도입 여부를 결정하세요. 기존 `ui-test-junit4` 방식은 테스트 대상 앱/단말이 필요하지만, AGP 9.5 이상에서는 Preview 기반의 Test Suites 통합도 검토할 수 있습니다. 후자는 현재 실험적입니다. 기존 독립형 `com.android.compose.screenshot` 플러그인은 공식 문서에서 유지보수 중단(deprecated path)을 안내합니다.

### AGP 9.5+ 실험적 Preview Screenshot Test Suite 예시

**최소 요구:** `AGP 9.5.0-alpha03+`, Compose Screenshot Engine `0.0.1-alpha16+`, JDK 17+, Compose 활성화. 해당 AGP 버전을 사용하지 않는 프로젝트에는 이 DSL을 적용하지 마세요.

`gradle.properties`:

~~~properties
android.experimental.enableScreenshotTest=true
android.experimental.testSuiteSupport=true
~~~

모듈의 `build.gradle.kts` 중 `android { }` 설정 예시:

~~~kotlin
android {
    testOptions {
        screenshotTests.create("screenshotTest") {
            engineVersion = "0.0.1-alpha16"
            // 실제 프로젝트에 존재하는 variant 이름으로 변경
            targetVariants.add("demoDebug")
            dependencies {
                implementation(libs.androidx.compose.ui.tooling)
                implementation(
                    "com.android.tools.screenshot:screenshot-validation-api:0.0.1-alpha16"
                )
            }
        }
    }
}
~~~

`src/screenshotTest/kotlin/...` 예시:

~~~kotlin
import androidx.compose.runtime.Composable
import androidx.compose.ui.tooling.preview.Preview
import com.android.tools.screenshot.PreviewTest

@PreviewTest
@Preview(name = "light", uiMode = 0x10)
@Preview(name = "dark", uiMode = 0x20)
@Composable
fun ThemePreviewTest() {
    AppTheme {
        ScreenContent()
    }
}
~~~

`AppTheme`과 `ScreenContent`는 앱이 제공하는 Composable로 교체해야 합니다. 코드 블록은 설정·핵심 API를 보여주는 **부분 예시**이며, 모듈·Gradle 프로젝트에 맞춘 통합 빌드와 Golden 생성은 별도로 진행해야 합니다. 세부 설정과 작업 이름은 [공식 Test Suites 안내](https://developer.android.com/studio/preview/compose-screenshot-testing-with-testsuites)를 확인하세요.

**버전:** 예제 API 기준 Compose UI Test **1.7.8**; 실제 프로젝트의 UI/UI Test 버전은 일치시키고 컴파일을 검증해야 합니다. <code>captureToImage()</code>는 Android API 26+가 요구됩니다.

**출처:** [Compose UI Test API](https://developer.android.com/reference/kotlin/androidx/compose/ui/test/SemanticsNodeInteraction) · [Screenshot 테스트 안내](https://developer.android.com/training/testing/ui-tests/screenshot) · [AGP Test Suites 기반 실험적 통합](https://developer.android.com/studio/preview/compose-screenshot-testing-with-testsuites)
